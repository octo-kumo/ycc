\section{Errors and diagnostics}
\label{sec:errors}

\subsection{Compile time}

Static checking is fatal: a rejected program compiles to nothing.
Diagnostics are one line each,

\begin{center}
\ic{line:col: error: message}
\end{center}

\noindent positioned in the user's source even when the compilation
splices imported files or prelude/runtime code into it. An error in an
imported file names that file, \ic{path:line:col: error: message}, with
the line counted in that file and the path as the import resolved it.
The checker reports a root
cause \emph{once} (Section~\ref{sec:poison}): after an error, the
expression gets the error type, which causes no follow-on errors
through the enclosing uses. Typical families:

\begin{itemize}[nosep]
\item name errors: \ic{undefined variable 'x'};
\item shape errors: \ic{record has no field 'f'};
\item operator typing: \ic{'++' needs a number target};
\item array operators: \ic{'+=' appended elements: expected [long], got long};
\item in-place only: \ic{arrays support only '+=' and '*=' (in place), not '-='};
\item call errors: \ic{call takes 2 args, got 1};
\item non-value use: \ic{cannot index long (only arrays and maps)};
\item void use: \ic{cannot bind a void value to 'x'}.
\end{itemize}

\noindent One limit is not a typing rule but a resource: the compiler
walks the program recursively (the parser, then the renamer, the
checker and the emitter), so an expression, a type or a block nested
deeper than \textbf{1000} is refused with the position that was too
deep, \ic{line:col: error: an expression nests deeper than 1000, the
compiler's limit}. Both compilers share the number, so the same program
is accepted or refused by each. A long chain counts too, once the
walks reach it: \ic{1+1+1+...} parses in a loop, but the checker and
the emitter follow it down, so a chain of a thousand terms is refused
the same way.

\subsection{Warnings}
\label{sec:warnings}

A program that compiles can still draw \emph{warnings}: code that is
legal but looks like a mistake. They go to \textbf{stderr}, one line
each, positioned like errors (an imported file's naming that file),

\begin{center}
\ic{line:col: warning: message}
\end{center}

\noindent and they never change the program: the binary is the same,
byte for byte, with them or without, and \ic{ycc -w} turns them off. The
std units never warn; a package warns when it compiles. What draws one:

\begin{itemize}[nosep]
\item a local binding nothing reads: \ic{unused variable 'x'} (or
  \ic{unused constant}, \ic{unused function}), or one only assigned to:
  \ic{variable 'x' is assigned but never read};
\item a value computed and dropped: \ic{the value of 'x' is not used},
  \ic{the result of '+' is not used} (for \ic{==} it adds \ic{did you
  mean '='?}). A call's value may be dropped, and so may \ic{ok \&\& f()};
\item \ic{unreachable code}: a statement after one that always returns;
\item \ic{'x' is assigned to itself} for \ic{x = x}, and \ic{'x < x' is
  always false} (or \ic{>}; \ic{x != x} is the NaN test and draws
  nothing);
\item \ic{division by zero}: \ic{/}, \ic{\%}, \ic{/=} or \ic{\%=} by a
  literal integer \ic{0};
\item a key given twice in a record or map literal --- \ic{duplicate field
  'a' in a record literal}, or \ic{duplicate key}. The last one wins;
\item a type that \ic{type} could name once: a record of two or more
  fields, or a union, written out in full more than once (\ic{the type
  \{...\} is written out 2 times}) or where an alias names it already
  (\ic{... is already declared as 'Point'}); two aliases of one type
  (\ic{type 'Spot' is the same type as 'Point'}); an alias declared
  twice (\ic{type 'Tag' is declared more than once}), where the last
  declaration counts.
\end{itemize}

\noindent Parameters, loop variables, top-level bindings and names
starting with \ic{\_} are never unused: \ic{let \_x = f();} keeps a
value on purpose.

\paragraph{Optional checks: \ic{-W N}}
\label{sec:wlevel}

Three checks are off by default, because in ordinary code they are a
habit rather than a mistake: a getter call or a bare \ic{a[i]} as a
statement reads fine. Raise the warning level to turn them on -- \ic{ycc
-W 1} (a project: \ic{ycc build -W 1}), which adds

\begin{itemize}[nosep]
\item \ic{the value of 'f()' is not used}: a call to a function that
  hands a value back, whose result nobody reads. A function that returns
  \ic{void}, one with no written return type, a builtin, and a name from
  another unit are all taken to return nothing and draw nothing;
\item \ic{the value computed here is not used}: a read or a literal used
  as a statement -- \ic{x.f}, \ic{a[i]}, \ic{a[1:2]}, \ic{\&x},
  \ic{*p}, a record, array or map literal, \ic{[x; n]}, \ic{x is B};
\item \ic{the 'else' branch is empty}: an \ic{if} whose \ic{else} does
  nothing. The void redesign (Section~\ref{sec:void}) made the branch
  unnecessary, so it can go; an \ic{else} that runs anything, and an
  \ic{if} with no \ic{else}, draw nothing.
\end{itemize}

\noindent Level \ic{0} (the default) is the set above. \ic{-W} with no
level, or one that is not a number, is an error. The level changes which
warnings are printed and nothing else: the binary is the same either way.

\subsection{Run time}

The compiled program traps --- writes a one-line message to stdout and
exits with status 1 --- on:

\begin{center}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{0.34\linewidth}@{\quad}>{\raggedright\arraybackslash}p{0.58\linewidth}@{}}
\toprule
condition & message \\
\midrule
array index outside \ic{[0, len)} & \ic{runtime error: index out of bounds} \\
division or remainder by zero & \ic{runtime error: division by zero} \\
shift by a negative count & \ic{runtime error: negative shift count} \\
\ic{unwrap(none)}, \ic{none!} & \ic{runtime error: unwrap of none} \\
slice assignment out of range & \ic{runtime error: slice assignment out of bounds} \\
\ic{a[lo:hi] = b}, wrong \ic{len(b)} & \ic{runtime error: slice assignment length mismatch} \\
match with no arm covering a value & \ic{runtime error: no match arm matched} \\
a union value cast to a member & \ic{runtime error: a union value cast to} \\
\quad it does not hold (Section~\ref{sec:type-unions}) & \quad\ic{a member it does not hold} \\
memory exhausted & \ic{runtime error: out of memory} \\
unbounded (non-tail) recursion & stack exhaustion: no limit, so the
  process dies on the guard page \\
\bottomrule
\end{tabular}
\end{center}

\noindent These messages go to \textbf{stdout} (the trap stubs use
\ic{write(1, ...)} directly), so a program's real output stays
recognizable; \ic{eputs} is the way to send diagnostics to stderr.

\noindent Fixed arrays trap exactly like heap arrays; slices never trap
(they clamp). Integer overflow is \emph{not} an error
(Section~\ref{sec:evaluation}).

\subsection{Exit status}

A successfully run program exits with the code it chose
(\ic{exit(code)} or falling off the end, which is \ic{0}); a trapped
program exits with \ic{1}. The compiler itself exits \ic{0} on success
(warnings or not), \ic{1} on a rejected input.

\subsection{Reproducibility}

The compiler is deterministic: the same input produces byte-identical
output on every run and in either implementation. This is checked
continuously by comparing the two compilers' output binaries byte for
byte, and by self-compilation (a compiler built by the compiler is
identical to the one that built it).
