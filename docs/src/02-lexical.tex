\section{Lexical structure}
\label{sec:lexical}

\subsection{Source text}

A program is a sequence of bytes, conventionally UTF-8. The lexer works
on bytes; only ASCII is significant to the grammar. Both \ic{"\bs n"} (LF) and \ic{"\bs r\bs n"} (CRLF) end a line. Positions reported
in diagnostics are 1-based line and column, the column counted in bytes.

\subsection{Comments}

\begin{lstlisting}
// a line comment runs to the end of the line
/* a block comment
   does not nest: the first */ closes it */
\end{lstlisting}

\noindent Comments are whitespace: they separate tokens and nothing more.

\subsection{Meta blocks}

A \emph{meta block} is compile-time code whose value becomes source text.
There are two forms, and they differ only in where the text lands:

\begin{lstlisting}
let count = #{ tally(n) }#;   // expression position: where the block was
#{ emit_table(); }#           // alone on a line: there, as statements
\end{lstlisting}

\noindent A block is \emph{not} a token and \ic{\#} is \emph{not} an escape
character. It is read before the lexer runs, in one pass over the file's bytes,
and only in \emph{code} position --- so inside a string literal, an f-string, a
byte string, a character literal, a line comment or a block comment, a
\ic{\#\{} is plain text and needs no escaping anywhere, and a generator may
emit literals holding \ic{\#\{} freely. A \ic{\#} in code position that is not
followed by \ic{\{} is an error, as is a \ic{\}\#} with no block open, a block
that never closes, and an unterminated string literal; each names its line.

The block's body is ordinary \textsf{Y}, compiled and run while the compiler
runs; what lands in the program's source is the \emph{rendering} of the body's
value --- what \ic{tostring} makes of it --- so the value need not be a \ty{str}
itself. A \ty{str} is its own rendering, so a value that is \emph{source text}
still has to be spelled as a literal before it lands: \ic{\#\{ quoted(name) \}\#},
not \ic{\#\{ name \}\#}, or the program sees a bare name where it expected code.
A body whose value is \ic{void} is an ordinary type error, because \ic{tostring}
has no case for it.

\paragraph{Where a block may sit.} A block may be at the top level or inside
another block. It may \emph{not} be in a \ic{def} or \ic{type} \emph{body}: in a
body, in-place emission would give compile-time-fixed values --- one call site
for every runtime caller --- and a silent ``never ran'' mode when nothing calls
it during generation.

A block inside a block is \emph{splicing}, at every level and with no second
meaning: the inner block's text is substituted into the \emph{source of the block
around it}, that source is compiled and run, and the outer block's own text is
substituted in turn --- innermost first. So \ic{\#\{ let a = \#\{ "1+1" \}\#; a
\}\#} resolves to \ic{2}: the inner block yields the text \ic{1+1}, the outer
block is then \ic{let a = 1+1; a}, and its \emph{value} --- not its source --- is
the \ic{a} it names, which is why the answer is \ic{2} and not \ic{let a = 1+1;
a}. A generator that generates a generator is ordinary nesting, and there is no
second dialect for it. Each level costs one more compile and one more run of the
generator inside the compiler, so nesting is capped at \textbf{8} and one level
over that is an error naming the cost.

\paragraph{Where the call goes.} Two cases, decided by the byte before the
\ic{\#\{}.

\emph{An operand position} --- the preceding non-space byte is \ic{(}, \ic{,},
\ic{=}, \ic{[}, \ic{\{}, \ic{;}, \ic{:}, \ic{?}, an operator, or the block starts
a line or follows a keyword such as \ic{return} --- keeps the call \emph{in
place}: the expression is \ic{\#\{ \ldots \}\#} itself, so the call yields a
\ty{str} and the surrounding position must want a \ty{str}. That is why
\ic{f(\#\{ quoted(s) \}\#, 2)} wants an \ic{s: str} parameter, and why
\ic{a[\#\{ i \}\#]} does not work at all: an index is a \ty{long}.

\emph{Mid-token} --- the preceding byte ends a token (a word character, \ic{)},
\ic{]}, \ic{.} or a literal's quote), so there is no operand position and a call
cannot go there --- the block's bytes are \emph{dropped} from the generator
program and the call is emitted as a statement immediately before the top-level
statement the block is in. This is safe precisely because it is mid-token: the
block is an adjunct between two adjacent tokens, and dropping an adjunct leaves
them adjacent. So \ic{def helper\#\{nm\}\#() -> long \{ 7 \}} becomes
\ic{def helper() -> long \{ 7 \}} in the generator, with \ic{nm} already
evaluated in the statement above it; \ic{obj\#\{i\}\#.field} becomes
\ic{obj.field}; \ic{1\#\{i\}\#} becomes \ic{1}.

\paragraph{An \ic{import} inside a block} is hoisted to the top of the generator
program, so the module is resolved exactly as an import at the top of a file
would be. It must come \emph{first} in its block, and it must end with a
semicolon; a block is not a file scope, and both mistakes are errors naming the
line. A block that emits an \ic{import} as text lands in the program if it lands
as a whole line, and nowhere at all if it lands mid-line.

\paragraph{Generated text is never re-scanned.} The pass reads the file once,
before the lexer; the text a block renders is spliced into the program and
nothing looks at it again. So a block may emit half a statement, and it may
\emph{not} emit a \ic{\#\{ \ldots \}\#} block --- generated text is not code
position, there is no generator to run it, and it is an error naming the
block. Nesting is therefore written, never generated: a block inside a block is
in the source, which is where the pass finds it. Unbalanced brackets in
generated text are the parser's problem, and the line map below points the error
at the block.

\paragraph{Lines.} Every line the pass generates carries the line of the
\ic{\#\{} it came from, because that is the honest origin --- the text has no
line of its own. A block's own text may be many lines: the piece is inserted at
the byte offset its \ic{\#\{} was scanned at, and the line map is rebuilt around
it, so the lines after it shift by however many it added. A diagnostic in
generated text therefore names the block's line, and one in the generator names
the source line the block's text came from.

\paragraph{The top level runs once per round.} A file's top level is the
generator's program --- the generator \emph{is} the file with each block replaced
by a call --- so with blocks in the file every top-level statement runs once to
build the generator and once in the program. A declaration is fine (\ic{def} and
\ic{type} hoist, and a \ic{let} a block reads should be pure), and so is text a
block generated, which the program runs once and the generator never ran at all;
any other top-level statement is a warning naming its line. Prefer a declaration
when the file holds a block.

Nesting adds rounds, so the count is once per round rather than twice. Where a
round cannot yet produce a block's text --- the inner block's, which is only known
a round later --- the pass leaves a stand-in there and leaves every top-level
statement that is neither a declaration nor carries a block out of that round's
generator program, so such a statement does not run in it. A top-level \ic{let}
is a declaration and so is kept, which is the sharp edge: an initializer that
reads a name a block \emph{generates} still fails in a stand-in round. Keep such
an initializer not merely pure but independent of what a block emits.

A thread or process primitive (\ic{spawn}, \ic{fork}, \ic{join}, \ic{mutex},
\ic{lock}, \ic{try\_lock}, \ic{sem}, \ic{post}, \ic{wait}) cannot be used in a
block --- it runs in a forked child, so it would be almost always a mistake ---
and neither can a name the pass injects (\ic{ycc\_meta\_expr},
\ic{ycc\_meta\_stmt}, \ic{ycc\_meta\_emit}).

\paragraph{Three limits, measured.} A name fragment needs a character of the
name beside it: \ic{def \#\{nm\}\#()} is not mid-token (nothing ends a token
there), a call cannot go in a header, and dropping its bytes would leave
\ic{def () -> long}, so it is an error. The generator holds the \ic{def} under
the \emph{short} name, so a generated name and its call sites have to be
generated together --- the source may not mention the full name. And a block
cannot be adjacent to another block: \ic{\}\#\#\{} is two blocks but
\ic{\}\#\{} is one block and then a brace, so write \ic{\#\{x\}\#b\#\{y\}\#}.

\subsection{Identifiers and keywords}

A \emph{word character} is a letter (\ic{A}--\ic{Z}, \ic{a}--\ic{z}), a
digit (\ic{0}--\ic{9}) or \ic{\_}, and an identifier is one word character
followed by any number of them:

\begin{align*}
\ty{identifier} &::= \ty{isalpha}~\{~\ty{isalnum}~\}
\end{align*}

\noindent \ic{isalpha} and \ic{isalnum} are the same test, a word
character: a digit may begin a name in the grammar, but a leading digit
always begins a number literal instead, so none does in practice. So
\ic{\_} is a word character and a digit is ordinary inside a name ---
\ic{is\_digit}, \ic{t0} and \ic{r64} are each a single identifier, not
three tokens.

The prefix \ic{y\_} is \emph{reserved} for the compiler's own generated
code, which calls its runtime helpers by those fixed names. A program may
nevertheless define one: that is the override hook, and the program's own
definition replaces the standard library's helper of that name for the
whole program, and it is the only way to reach the runtime's own copies.

The keywords are:
\begin{center}
\ic{let} \ic{const} \ic{def} \ic{native} \ic{if} \ic{else} \ic{while} \ic{for}
\ic{foreach} \ic{in} \ic{return} \ic{break} \ic{continue} \ic{true}
\ic{false}
\end{center}

\ic{native} is a whole word, so \ic{native\_io} and \ic{natives} are
ordinary names; it is not a \emph{contextual} keyword (the list below),
because the declaration it introduces has no other spelling.

\subsection{Literals}
\label{sec:literals}

\paragraph{Integers.} Decimal, binary (\ic{0b1010}) and hexadecimal
(\ic{0x1F}) radix literals are supported. Any of them may group digits
with \ic{\_}, which is ignored: a radix literal (\ic{0x} / \ic{0b},
either case) in any position after the prefix (\ic{0xFF\_FF},
\ic{0b1010\_1010}), a decimal one anywhere after its first digit
(\ic{1\_000\_000}; a leading \ic{\_} starts an identifier instead).
A prefix needs a digit of its radix: \ic{0x}, \ic{0b\_} and \ic{0b2}
are errors (\ic{binary literal '0b2' has no digits}), one for the whole
word.
There is no octal form: \ic{017} is decimal seventeen. All integer
literals are \ty{long} (64-bit). A radix literal spells the 64 bits
themselves, so a mask may set the top bit:
\ic{0xFFFF\_FFFF\_FFFF\_FFFF} is \ic{-1} and
\ic{0x8000\_0000\_0000\_0000} the smallest \ty{long}; digits past 64
bits wrap away (modulo $2^{64}$).

\paragraph{Floats.} A digit sequence with a decimal point and/or an
exponent: \ic{1.5}, \ic{1.5e+3}, \ic{2.0e-1}. \ic{\_} may group digits
after the first digit of the whole part, of the fraction and of the
exponent: \ic{1\_000.5}, \ic{0.000\_001}, \ic{1e1\_0} (\ic{1.\_5} and
\ic{1e\_5} are parse errors). A dot followed by a non-digit is
\emph{not} a fractional part --- \ic{a..b} lexes as \ic{a}, \ic{..},
\ic{b}. Float literals are IEEE-754 binary64 (\ty{float}).

The compiler decides a float literal's value itself, and rounds it
\emph{once}, to nearest even, from the digits as written --- so a
literal is the double \ic{strtod}, C's \ic{printf} and Python's \ic{float}
would give, however many digits it has: \ic{9007199254740991.0} is
$2^{53}-1$ and exact, \ic{1e23} is the nearest double to $10^{23}$, and
both were a ulp out before. Magnitude past the range becomes \ic{inf} or
\ic{0.0}, as IEEE says (\ic{1e400}, \ic{-1e-400}); a magnitude nobody
means --- a net power of ten (the exponent less the digits after the dot)
past 100000 --- is an error instead, since it is a slip and not a value.
A \emph{zero} mantissa is exempt however large that exponent, because
zero times anything is zero: \ic{0e999999} is exactly \ic{0.0} and C's
\ic{strtod} takes it. A literal is a constant: the generated code holds
its bits, and no decimal is parsed at runtime.

That rounding is exact everywhere measured except one band, which is
recorded rather than claimed: a literal between about \ic{1e-327} and
\ic{1e-367} is mis-parsed into a nonzero \emph{subnormal} where the
value is exactly zero. Over 725 literals spanning those exponents, 302
are wrong and every one of the 302 should be zero. It is a band and not
a threshold --- \ic{1e-327} is wrong and \ic{1e-326} right, and both
\ic{1e-367} and \ic{1e-400} are right. Nothing outside it is affected: the
whole subnormal range from \ic{5e-324} up rounds correctly, and so does
every ordinary literal. The wrong answers are subnormals with a mantissa
near $2^{30}$, one whole step of the 32-bit-at-a-time narrowing that
makes \ic{1e300} cheap.

\paragraph{Strings.} Double-quoted byte strings:

\begin{center}
\begin{tabular}{ll}
\toprule
escape & meaning \\
\midrule
\ic{\bs n} \ic{\bs t} \ic{\bs r} & LF, HT, CR \\
\ic{"\bs "} \ic{"\bs ""} \ic{"\bs '"} & backslash, quote \\
\ic{\bs xHH} & byte with hex value \ic{HH} \\
\ic{\bs c} (any other \ty{c}) & \ty{c}; the backslash is dropped \\
\bottomrule
\end{tabular}
\end{center}

\noindent An escape is read as a single byte, and an unrecognised
\ic{\bs c} simply drops the backslash (\ic{"q\bs q"} is \ic{"qq"}), so a
NUL is spelled \ic{"\bs x00"} --- which is not \ic{"\bs0"} (that is the
character \ic{0}). A \ic{str} is a length-prefixed byte string, so an
escaped NUL inside one is ordinary data and \ic{len} counts it (use
\ic{[byte]} arrays, Section~\ref{sec:builtin-bytes}, for bulk binary
data).

\paragraph{Byte strings.} \ic{b"..."} and \ic{b'...'} are \emph{byte
string literals}: a \ic{[byte]} value spelled like a Python \ic{bytes}
literal. The escapes are the string escapes above, so binary data writes
naturally: \ic{b"\bs x7fELF"} is the four-byte ELF magic. Either quote
spells the same type; single quotes exist only for byte strings and
character literals.

\paragraph{Character literals.} \ic{c'a'} is a \emph{character
literal}: exactly one byte, of type \ty{byte}, read with the string
escapes above (\ic{c'\bs n'} is 10, \ic{c'\\'} is 92). It compares
against a \ty{long} directly --- a \ty{byte} widens --- so a keypress
test is \ic{k == c'q'}, and it needs an annotation to become a number:
\ic{let q: long = c'q';}. Single quotes exist only for byte strings and
character literals, and a \emph{bare} \ic{'a'} is neither: it is
reported where it is written, naming the spelling
(\ic{a character literal is spelled c'a' ...}).

\paragraph{Format strings.} \ic{f"..."} is a string literal with
\emph{fields}, as in Python:
\begin{center}
\ic{f"\{name\} is \{age\} (\{share:.1\%\})"}
\end{center}
\noindent A field \ic{\{e\}} becomes \ic{tostring(e)}, and
\ic{\{e:spec\}} becomes \ic{e} formatted as \ty{spec} says
(Section~\ref{sec:format-spec}). The text around the fields takes the
string escapes, and \ic{\{\{} and \ic{\}\}} (or \ic{\bs\{} and
\ic{\bs\}}) are literal braces. An f-string is sugar for concatenation:
\ic{f"a\{x\}b"} means \ic{"a" + tostring(x)} \ic{+ "b"}, a \ty{str} like
any other.

A field holds one expression --- calls, string literals, record literals
and nested f-strings included --- and may span lines; an error inside it
points at its own line and column. The expression ends at the first
\ic{\}} or \ic{:} outside brackets, except a \ic{:} that answers a
\ic{?}: \ic{\{ok ? a : b\}} works, while a cons has to be parenthesised,
\ic{\{(x :: xs)\}}. A \ic{?} that is part of a \ic{?.} (Section~
\ref{sec:opt-propagation}) answers nothing, so the \ic{:} after it is
the spec's own: \ic{f"\{o?.port:x\}"\}} is \ic{o?.port} as \ic{x}. The spec
is plain text up to the field's \ic{\}}; it cannot hold another field.

\paragraph{Booleans and none.} \ic{true}, \ic{false}. The empty option
is spelled \ic{none}, a predeclared name rather than a keyword
(Section~\ref{sec:type-options}). There is no \ic{null}: the word is an
ordinary (undefined) identifier.

\paragraph{Maximal munch.} The lexer always takes the longest operator
that matches, exactly like C:
\begin{itemize}[nosep]
\item \ic{x+++y} is \ic{x ++ + y}, not \ic{x + ++y};
\item \ic{x--y} is \ic{x-- y} (a parse error), not \ic{x - -y};
      write \ic{x - -y} when negation is meant;
\item \ic{/=} is one token; \ic{//} starts a comment, and
      \ic{/ == y} must be written with a space to divide;
\item \ic{x>{}>{}>=1} is the compound \ic{x >{}>{}>= 1};
\item \ic{x?.y} is the propagation operator, not a conditional \ic{x} whose
      arm starts with \ic{.y} (Section~\ref{sec:opt-propagation}).
\end{itemize}

\paragraph{Contextual keywords.} These words are ordinary identifiers to
the lexer and mean their keyword only where the syntax calls for one, so a
program may bind a name like any of them and keep it:

\begin{itemize}[nosep]
\item \ic{none} is a predeclared name (Section~\ref{sec:type-options}), not
  a keyword at all;
\item \ic{match} is the match-expression keyword only when an expression
  and \ic{\{} follow it, and \ic{type} starts a type alias only when
  followed by \ic{name =};
\item the type names \ic{long}, \ic{byte}, \ic{bool}, \ic{float},
  \ic{str}, \ic{int}, \ic{void}, \ic{mutex} and \ic{sem} are names in a
  type position only --- in an expression they are ordinary variables;
\item the thread and process words \ic{spawn}, \ic{fork}, \ic{lock},
  \ic{try\_lock}, \ic{join}, \ic{post} and \ic{wait} begin their form only
  before a block or an operand (Section~\ref{sec:expr-grammar}), so
  \ic{join} may equally be a function's name;
\item \ic{self} names the enclosing function inside a \ic{def} body, and
  is an error anywhere else (\ic{'self' outside of a function}).
\end{itemize}
